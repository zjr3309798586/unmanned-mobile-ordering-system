# 云豹小点无人移动点餐系统代码详解文档

## 1. 项目整体说明

本项目名称为“云豹小点无人移动点餐系统”，包含前台用户端、后台管理端、微信小程序端和 Java 后端。

项目当前采用的技术：

- 前台用户端：原生 HTML + CSS + JavaScript
- 后台管理端：原生 HTML + CSS + JavaScript
- 微信小程序端：微信原生小程序语法
- 后端：Java 11 + Spring Boot 2.7 + MyBatis + MySQL
- 数据库：MySQL

当前项目的主要功能：

- 用户浏览首页、点餐、查看商品详情
- 用户登录后加入购物车
- 用户提交订单
- 用户查看订单、取消订单、再来一单
- 用户开通省钱卡、领取优惠券
- 后台管理员登录
- 后台管理商品、分类、订单、优惠券、首页 Banner
- 后台查看数据看板和统计分析

## 3. 后端启动入口

后端启动类：

```text
backend/src/main/java/com/unmanned/ordering/UnmannedOrderingApplication.java
```

代码：

```java
@SpringBootApplication
@MapperScan("com.unmanned.ordering.mapper")
public class UnmannedOrderingApplication {
    public static void main(String[] args) {
        SpringApplication.run(UnmannedOrderingApplication.class, args);
    }
}
```

解释：

- `@SpringBootApplication` 表示这是 Spring Boot 项目的启动类。
- `@MapperScan("com.unmanned.ordering.mapper")` 表示扫描 mapper 包里的 MyBatis 数据库接口。
- `SpringApplication.run(...)` 用来启动整个后端服务。

在 IDEA 中运行这个类，后端就会启动。

启动成功后访问：

```text
http://127.0.0.1:8080/
```

后台登录地址：

```text
http://127.0.0.1:8080/admin/login.html
```

接口健康检查：

```text
http://127.0.0.1:8080/api/health
```

## 4. 后端分层结构

后端采用常见的 Controller、Service、Mapper 三层结构。

### 4.1 Controller 层

Controller 负责接收前端请求。

位置：

```text
backend/src/main/java/com/unmanned/ordering/controller
```

可以理解为“接口入口”。

例如前端请求商品列表：

```text
GET /api/products
```

这个请求会进入：

```text
ProductController.java
```

### 4.2 Service 层

Service 负责写业务逻辑。

位置：

```text
backend/src/main/java/com/unmanned/ordering/service
```

可以理解为“真正处理事情的地方”。

例如加入购物车、提交订单、计算优惠券是否可用，都在 Service 中处理。

核心类：

```text
OrderingService.java
```

### 4.3 Mapper 层

Mapper 负责操作数据库。

位置：

```text
backend/src/main/java/com/unmanned/ordering/mapper
```

可以理解为“写 SQL 查数据库的地方”。

例如：

- `ProductMapper` 查询商品表
- `CartMapper` 查询和修改购物车表
- `OrderMapper` 查询和修改订单表

### 4.4 Model 层

Model 是数据对象。

位置：

```text
backend/src/main/java/com/unmanned/ordering/model
```

例如：

- `Product` 表示商品
- `Order` 表示订单
- `CartItem` 表示购物车商品
- `Coupon` 表示优惠券
- `UserProfile` 表示用户会员资料

### 4.5 Request 层

Request 是前端提交给后端的数据格式。

位置：

```text
backend/src/main/java/com/unmanned/ordering/request
```

例如：

- `AddCartItemRequest`：加入购物车请求
- `CreateOrderRequest`：提交订单请求
- `ProductRequest`：后台新增或编辑商品请求
- `CouponRequest`：后台新增或编辑优惠券请求

## 6. OrderingService 核心业务详解

文件：

```text
backend/src/main/java/com/unmanned/ordering/service/OrderingService.java
```

这是后端最重要的类。

### 6.1 查询商品

方法：

```java
public List<Product> listProducts(String categoryId, String keyword)
```

作用：

- 查询启用状态的商品
- 支持按分类筛选
- 支持按关键词搜索

调用：

```text
ProductController -> OrderingService -> ProductMapper
```

### 6.2 加入购物车

方法：

```java
public CartSummary addCartItem(String userId, AddCartItemRequest request)
```

逻辑：

1. 根据 `productId` 查询商品。
2. 获取规格 `spec`。
3. 判断购物车里是否已经有同商品同规格。
4. 如果有，就增加数量。
5. 如果没有，就新增购物车记录。
6. 返回购物车汇总。

对应数据库表：

```text
cart_items
```

### 6.3 获取购物车汇总

方法：

```java
public CartSummary getCartSummary(String userId)
```

逻辑：

1. 查询当前用户购物车商品。
2. 计算总数量。
3. 计算总金额。
4. 返回 `CartSummary`。

前端点餐页底部结算栏、购物车页都会用这个结果。

### 6.4 提交订单

方法：

```java
public Order createOrder(String userId, CreateOrderRequest request)
```

这是整个项目最核心的流程。

逻辑：

1. 查询当前用户购物车。
2. 如果购物车为空，抛出错误。
3. 把购物车商品转换成订单商品。
4. 计算商品总价。
5. 调用 `calculateDiscount()` 计算优惠金额。
6. 计算实付金额。
7. 创建订单号。
8. 写入 `orders` 表。
9. 写入 `order_items` 表。
10. 增加商品销量。
11. 如果使用了优惠券，标记优惠券已使用。
12. 更新用户消费统计。
13. 清空购物车。
14. 返回订单。

对应数据库表：

```text
orders
order_items
cart_items
user_coupons
products
user_profiles
```

### 6.5 计算优惠券

方法：

```java
private BigDecimal calculateDiscount(String userId, String couponId, BigDecimal totalAmount)
```

逻辑：

1. 如果没有选择优惠券，优惠金额为 0。
2. 查询用户是否已经领取该优惠券。
3. 判断优惠券是否可用。
4. 判断订单金额是否达到使用门槛。
5. 返回优惠金额。

这解决了“没达标也能用优惠券”的问题。

### 6.6 取消订单

方法：

```java
public Order cancelOrder(String userId, String orderId)
```

逻辑：

1. 查询订单。
2. 已完成订单不能取消。
3. 如果订单已取消，直接返回。
4. 回滚订单影响。
5. 修改订单状态为 `CANCELED`。

回滚订单影响包括：

- 减少商品销量
- 恢复优惠券
- 回退用户消费统计

### 6.7 后台完成订单

方法：

```java
public Order completeOrder(String orderId)
```

逻辑：

1. 后台根据订单 ID 查询订单。
2. 已取消订单不能完成。
3. 修改订单状态为 `COMPLETED`。

后台订单管理点击“完成”时会调用这个方法。

### 6.8 再来一单

方法：

```java
public CartSummary repeatOrder(String userId, String orderId)
```

逻辑：

1. 查询历史订单。
2. 遍历订单商品。
3. 把订单商品重新加入购物车。
4. 返回购物车汇总。

### 6.9 省钱卡和优惠券领取

开通省钱卡：

```java
public UserProfile openSavingCard(String userId)
```

领取优惠券：

```java
public UserCoupon claimCoupon(String userId, String couponId)
```

领取优惠券时会判断：

```java
if (!isSavingCardMember(profile)) {
    throw new BusinessException(400, "请先开通省钱卡后领取优惠券");
}
```

所以用户必须先开通省钱卡才能领取优惠券。

### 10.1 common.js

`common.js` 是前台 H5 最重要的公共 JS。

接口地址逻辑：

```js
var defaultApiBaseUrl = window.location.protocol === "file:"
  ? "http://127.0.0.1:8080/api"

```

意思是：

- 如果直接双击 HTML 用 `file://` 打开，则请求 `http://127.0.0.1:8080/api`
- 如果通过 `http://127.0.0.1:8080/` 打开，则请求当前域名下的 `/api`

## 17. 常见问题

### 17.1 为什么必须先登录才能加入购物车？

因为购物车是按用户保存的。后端需要通过 `X-User-Token` 找到当前用户。

### 17.2 为什么优惠券必须先开通省钱卡才能领取？

这是业务规则。后端在 `OrderingService.claimCoupon()` 中判断用户会员等级是否包含“省钱卡”。

### 17.3 为什么订单提交后购物车会清空？

因为购物车商品已经变成正式订单商品，所以后端在 `createOrder()` 最后会调用 `cartMapper.clear(userId)`。

### 17.4 为什么后台修改商品后前台会变化？

因为前台点餐页每次加载都会调用 `/api/products`，而这个接口读取的是数据库中的最新商品数据。

### 17.5 为什么小程序真机不能用 127.0.0.1？

`127.0.0.1` 在手机上表示手机自己，不是电脑。真机调试需要把接口地址改成电脑局域网 IP，正式上线需要 HTTPS 域名。
