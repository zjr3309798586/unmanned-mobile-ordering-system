## 1. 总则

### 1.1 规范等级

本规范条目按强制程度分为三个等级:

- **【强制】** 必须遵守。违反此条目应视为代码缺陷,不允许合并入主干分支。
- **【推荐】** 应尽量遵守。如有合理理由可不遵守,但需在注释中说明。
- **【参考】** 建议遵守。可根据实际情况灵活处理。

### 1.2 适用范围

本规范适用于本项目下所有源代码,包括:

- H5 前端:`/css/*.css`、`/js/*.js`、`/*.html`
- 微信小程序:`/miniprogram/**`
- 后端服务:`/backend/src/main/java/**`、`/backend/src/main/resources/**`
- 设计与文档:`/docs/**`

### 1.3 基本原则

- **可读性优先**:代码首先是写给人看的,其次才是给机器执行的。
- **一致性优先**:与本项目已有风格保持一致,优先于个人偏好。
- **简单优先**:能用简单方式解决的,不引入复杂工具。

## 2. 项目目录结构规范

### 2.1 【强制】根目录名

项目根目录名应使用**英文小写 + 连字符**,不得使用中文或空格。

- 正例:`yunbao-xiaodian/`
- 反例:`前台页面/`、`my project/`

> 说明:中文路径在跨平台部署、Git 提交、命令行工具中常引发编码问题。

### 2.2 【强制】顶层目录结构

```
yunbao-xiaodian/
├── h5/                  H5 前端源码
│   ├── pages/             HTML 页面
│   ├── css/               样式文件
│   ├── js/                脚本文件
│   └── images/            图片资源
├── miniprogram/         微信小程序源码
├── backend/             后端 Spring Boot 服务
├── docs/                项目文档
├── admin/               管理后台(如有)
├── .gitignore
├── .editorconfig
└── README.md
```

### 2.3 【推荐】资源分类目录

`images/` 内应按用途分子目录:

```
images/
├── nav/        底部导航图标
├── home/       首页专用素材
├── menu/       点餐页商品图
├── mascot/     吉祥物相关
└── common/     跨页面通用
```

### 2.4 【强制】不得提交到仓库的目录

以下目录及文件**不得**提交到 Git 仓库,应写入 `.gitignore`:

- `backend/target/`(Maven 编译产物)
- `backend/*.log`(运行日志)
- `node_modules/`
- `.idea/`、`.vscode/`(IDE 个人配置)
- `*.local.*`(本地配置)

## 3. 命名规范

### 3.1 【强制】文件命名

| 类型             | 风格       | 示例                       |
| ---------------- | ---------- | -------------------------- |
| HTML 文件        | 小写连字符 | `saving-card.html`         |
| CSS 文件         | 小写连字符 | `mine.css`                 |
| JS 文件          | 小写连字符 | `cart.js`                  |
| Java 文件        | 大驼峰     | `CouponController.java`    |
| 小程序页面目录   | 小写连字符 | `pages/saving-card/`       |
| 图片资源         | 小写连字符 | `home-banner-1.png`        |

### 3.2 【强制】HTML / CSS 类名

采用 **kebab-case(小写连字符)**,语义化命名,不得使用拼音或缩写。

- 正例:`.cart-item`、`.coupon-drawer`、`.pay-bar`
- 反例:`.cartItem`、`.gwc_item`、`.box1`

### 3.3 【推荐】CSS 命名层级

采用类 BEM 简化形式:`.块名-元素名--状态名`。

- 块(Block):`.cart-item`
- 元素(Element):`.cart-item__name`(或简写为 `.ci-name`,本项目采用简写)
- 状态(Modifier):`.cart-item.is-selected`、`.is-disabled`、`.is-open`

### 3.4 【强制】JavaScript 命名

| 类型     | 风格         | 示例                  |
| -------- | ------------ | --------------------- |
| 变量     | 小驼峰       | `selectedCoupon`      |
| 函数     | 小驼峰,动词开头 | `renderCart()`、`openDrawer()` |
| 常量     | 全大写下划线 | `MAX_RETRY_COUNT`     |
| 构造函数 | 大驼峰       | `OrderingApp`         |
| 私有变量 | 下划线前缀   | `_internalState`      |

### 3.5 【强制】Java 命名

| 类型     | 风格     | 示例                        |
| -------- | -------- | --------------------------- |
| 类       | 大驼峰   | `CouponService`             |
| 方法     | 小驼峰   | `getUserCoupons()`          |
| 变量     | 小驼峰   | `discountAmount`            |
| 常量     | 全大写下划线 | `DEFAULT_PAGE_SIZE`     |
| 包       | 全小写   | `com.unmanned.ordering.controller` |

### 3.6 【强制】数据库命名

- 表名:小写下划线,复数。如 `user_coupons`、`order_items`
- 字段名:小写下划线。如 `condition_amount`、`created_at`

## 4. HTML 编码规范

### 4.1 【强制】文档声明与编码

每个 HTML 文件首行必须为 `<!DOCTYPE html>`,`<head>` 中必须声明 UTF-8 编码与 viewport。

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
  <title>页面标题 - 云豹小点</title>
</head>
```

### 4.2 【强制】缩进与格式

- 使用 **2 个空格** 缩进,不得使用 Tab。
- 标签、属性名一律小写。
- 属性值统一使用双引号 `"`。

### 4.3 【强制】语义化标签

应使用具有明确语义的标签,不得滥用 `<div>`。

| 用途       | 应使用             | 不应使用      |
| ---------- | ------------------ | ------------- |
| 页面头部   | `<header>`         | `<div class="header">` |
| 主内容区   | `<main>`           | `<div class="main">`   |
| 导航       | `<nav>`            | `<div class="nav">`    |
| 文章/卡片  | `<article>`/`<section>` | `<div>`          |
| 按钮       | `<button>`         | `<div onclick>` |

### 4.4 【强制】图片 alt 属性

所有 `<img>` 必须包含 `alt` 属性。装饰性图片可设为空字符串 `alt=""`,内容图片需有描述。

```html
<img src="images/home-banner-1.png" alt="新人首单立减">  ✅
<img src="images/home-banner-1.png">                    ❌
```

### 4.5 【推荐】无障碍属性

交互元素应包含 `aria-label`,SVG 图标应配 `aria-hidden="true"` 或 `<title>`。

```html
<button class="ct-back" type="button" aria-label="返回">
  <svg aria-hidden="true">...</svg>
</button>
```

## 5. CSS 编码规范

### 5.1 【强制】缩进与格式

- 使用 **2 个空格** 缩进。
- 每条声明独占一行,以分号结尾。
- 冒号后保留 1 个空格,冒号前无空格。
- 选择器与 `{` 之间保留 1 个空格。

```css
/* 正例 */
.cart-item {
  display: flex;
  padding: 16px;
  border-radius: 12px;
}

/* 反例 */
.cart-item{display:flex;padding:16px}
```

### 5.2 【强制】颜色与尺寸使用变量

全局色彩、字号、圆角等**不得在多个文件硬编码**,必须定义在 `:root` 变量中统一使用。

```css
/* tokens.css(或 common.css 顶部) */
:root {
  --color-primary: #005bbf;
  --color-primary-container: #1a73e8;
  --color-price: #FF4D4F;
  --color-text: #191c23;
  --color-text-sub: #575f6b;
  --radius-card: 16px;
  --shadow-card: 0 2px 8px rgba(0, 0, 0, 0.04);
}

/* 使用 */
.cart-item {
  background: #fff;
  border-radius: var(--radius-card);
  box-shadow: var(--shadow-card);
}
```

### 5.3 【强制】禁止使用 `!important`

除以下两种情况外,**不得**使用 `!important`:

1. 覆盖第三方库样式。
2. 工具类样式(如 `.is-hidden`)。

如必须使用,需在注释中说明原因。

### 5.4 【推荐】选择器最大嵌套层级

CSS 选择器嵌套**不超过 3 层**,避免过度耦合 DOM 结构。

```css
/* 推荐 */
.cart-item .ci-name { font-size: 14px; }

/* 不推荐 */
.cart-card .cart-items .cart-item .ci-body .ci-row1 .ci-name { font-size: 14px; }
```

### 5.5 【强制】响应式与固定定位

H5 应限制最大宽度为 **430px** 并居中显示。所有 `position: fixed` 元素必须采用以下模式居中:

```css
.pay-bar {
  position: fixed;
  bottom: 0;
  left: 50%;
  transform: translateX(-50%);
  max-width: 430px;
  width: 100%;
}
```

### 5.6 【参考】属性书写顺序

建议按以下顺序组织 CSS 属性,提升可读性:

1. 定位:`position`、`top`、`right`、`bottom`、`left`、`z-index`
2. 盒模型:`display`、`flex`、`grid`、`width`、`height`、`padding`、`margin`
3. 排版:`font-family`、`font-size`、`line-height`、`color`、`text-align`
4. 视觉:`background`、`border`、`border-radius`、`box-shadow`
5. 动画:`transition`、`animation`

## 6. JavaScript 编码规范

### 6.1 【强制】缩进与格式

- 使用 **2 个空格** 缩进。
- 语句末尾**必须**加分号。
- 字符串使用双引号 `"`,模板字符串除外。
- `{` 不换行,`}` 单独占一行。

```javascript
// 正例
function renderCart(items) {
  if (items.length === 0) {
    return;
  }
  items.forEach(function (it) {
    console.log(it.name);
  });
}
```

### 6.2 【强制】变量声明

- 优先使用 `var`(本项目当前为 ES5 风格,统一保持)。
- 同一文件内必须风格一致,不得 `var`/`let`/`const` 混用。
- 所有变量在使用前必须先声明。

### 6.3 【强制】严格相等

判断值是否相等,**必须**使用 `===` 和 `!==`,不得使用 `==` 和 `!=`。

```javascript
if (status === "AVAILABLE") { ... }  ✅
if (status == "AVAILABLE")  { ... }  ❌
```

### 6.4 【强制】空值与类型转换

- 判断空值优先使用 `value == null`(同时判断 `null` 和 `undefined`)或显式判断。
- 数值转换使用 `Number(x)`,字符串转换使用 `String(x)`,布尔转换使用 `Boolean(x)`。
- 不得使用隐式转换运算符 `+x`、`!!x`(除非有充分理由)。

### 6.5 【强制】函数职责单一

一个函数**只做一件事**,行数原则上不超过 50 行。超过应拆分。

```javascript
// 反例:一个函数干了 3 件事
function handlePay() {
  // 1. 校验登录态
  // 2. 计算优惠
  // 3. 调用下单接口
}

// 正例:拆分
function checkLogin() { ... }
function calcDiscount() { ... }
function submitOrder() { ... }
function handlePay() {
  if (!checkLogin()) return;
  var saved = calcDiscount();
  submitOrder(saved);
}
```

### 6.6 【强制】避免全局污染

业务代码必须包裹在 `DOMContentLoaded` 或 IIFE 中,**不得**向 `window` 挂载业务变量。

```javascript
// 正例
document.addEventListener("DOMContentLoaded", function () {
  var cart = { items: [] };
  // ...业务逻辑
});

// 唯一允许挂载到 window 的是项目命名空间
window.OrderingApp = { ... };
```

### 6.7 【强制】错误处理

所有异步请求(`Promise` / `fetch` / `XMLHttpRequest`)必须包含 `.catch()` 或 `try/catch`,不得静默失败。

```javascript
app.get("/cart")
  .then(function (data) { renderCart(data); })
  .catch(function (e) {
    if (app.showMessage) app.showMessage(e.message || "加载失败");
  });
```

### 6.8 【强制】XSS 防护

所有从接口、用户输入获取的字符串拼接到 HTML 时,**必须**经过 `escapeHtml()` 转义。

```javascript
itemsBox.innerHTML = '<h4>' + escapeHtml(it.productName) + '</h4>';  ✅
itemsBox.innerHTML = '<h4>' + it.productName + '</h4>';               ❌
```

## 7. 微信小程序编码规范

### 7.1 【强制】页面文件结构

每个页面必须包含且只包含以下 4 个文件:

```
pages/cart/
├── index.js     页面逻辑
├── index.wxml   页面结构
├── index.wxss   页面样式
└── index.json   页面配置
```

### 7.2 【强制】Page 数据初始化

`Page({ data: { ... } })` 中所有字段必须初始化,且类型与运行时一致。**不得**在 `data` 中只声明部分字段,然后运行时再添加新字段。

### 7.3 【强制】事件命名

事件处理函数命名采用 `on` + 动作 或 动词 形式。

- 正例:`onPay`、`openDrawer`、`pickCoupon`
- 反例:`pay1`、`click1`、`fn`

### 7.4 【强制】单位规范

布局尺寸**必须**使用 `rpx`(750rpx = 屏宽),字号可使用 `rpx` 或 `px`。

```wxss
/* 正例 */
.cart-item { padding: 32rpx; font-size: 28rpx; }

/* 反例 */
.cart-item { padding: 16px; }
```

### 7.5 【强制】图片加载

- 本地图片路径以 `/images/` 开头(绝对路径)。
- 远程图片必须使用 HTTPS,且域名已在小程序后台配置。
- 所有 `<image>` 必须设置 `mode` 属性。

```html
<image src="/images/menu-product.png" mode="aspectFill"/>  ✅
<image src="../../images/x.png"/>                          ❌
```

### 7.6 【强制】业务逻辑不得写在 WXML

WXML 中不得包含复杂表达式。计算逻辑应在 `data` 或 `wxs` 中完成。

```html
<!-- 反例 -->
<text>{{(price * quantity - discount).toFixed(2)}}</text>

<!-- 正例 -->
<text>{{payText}}</text>  <!-- payText 在 js 中算好 -->
```

## 8. Java 后端编码规范

### 8.1 【强制】分层架构

后端遵循经典三层架构,**不得**跨层调用:

```
Controller(接收请求)
   ↓
Service(业务逻辑)
   ↓
Mapper(数据访问)
   ↓
Database
```

- `Controller` 不得直接调用 `Mapper`。
- `Service` 不得依赖 `Controller`。
- 包路径:`controller`、`service`、`mapper`、`model`、`request`、`exception`、`config`、`common`。

### 8.2 【强制】Controller 规范

```java
@RestController
@RequestMapping("/api/coupons")
public class CouponController {

    @Resource
    private CouponService couponService;

    @GetMapping
    public Result<List<CouponVO>> list(@RequestHeader("X-User-Token") String token) {
        return Result.success(couponService.list(token));
    }
}
```

- 类必须加 `@RestController` 或 `@Controller` 注解。
- URL 必须以 `/api/` 前缀开头。
- 返回值必须统一包装为 `Result<T>` 或对应 VO。
- 不得在 Controller 中写业务逻辑。

### 8.3 【强制】参数校验

请求参数必须使用 `javax.validation` 注解校验,**不得**在方法体内手动 `if (xx == null)`。

```java
public class CreateOrderRequest {
    @NotBlank(message = "取餐方式不能为空")
    private String pickupType;

    @NotNull
    private Long productId;
}
```

### 8.4 【强制】异常处理

业务异常必须使用项目统一的 `BusinessException`,并由全局异常处理器 `GlobalExceptionHandler` 捕获,**不得**在 Controller 中 `try/catch` 后返回错误码。

```java
// 正例
if (coupon == null) {
    throw new BusinessException("优惠券不存在");
}

// 反例
if (coupon == null) {
    return Result.fail("优惠券不存在");
}
```

### 8.5 【强制】事务管理

涉及多表写入的方法必须加 `@Transactional`,并声明回滚条件。

```java
@Transactional(rollbackFor = Exception.class)
public Order createOrder(CreateOrderRequest req) { ... }
```

### 8.6 【推荐】SQL 规范

- MyBatis Mapper XML 中的 SQL 关键字大写。
- 复杂 SQL 必须加注释说明用途。
- **禁止** `SELECT *`,必须列出字段。

## 9. 接口与数据规范

### 9.1 【强制】接口路径

- 所有接口以 `/api/` 开头。
- 资源名使用复数小写。
- 路径中不得包含动词,动词通过 HTTP Method 表达。

| 操作     | Method | Path                  |
| -------- | ------ | --------------------- |
| 列表     | GET    | `/api/coupons`        |
| 详情     | GET    | `/api/coupons/{id}`   |
| 创建     | POST   | `/api/coupons`        |
| 更新     | PATCH  | `/api/coupons/{id}`   |
| 删除     | DELETE | `/api/coupons/{id}`   |
| 子动作   | POST   | `/api/coupons/{id}/claim` |

### 9.2 【强制】响应结构

所有接口统一返回结构:

```json
{
  "success": true,
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

失败响应:

```json
{
  "success": false,
  "code": 4001,
  "message": "优惠券已领取",
  "data": null
}
```

### 9.3 【强制】字段命名

- JSON 字段名采用**小驼峰**:`couponId`、`discountAmount`、`createdAt`。
- 后端 Java 实体字段与 JSON 一致,数据库字段小写下划线,通过 MyBatis 映射。
- **前端不得使用 `a || b` 兼容多个字段名**,后端必须固定一种。

### 9.4 【强制】时间格式

所有时间字段统一使用 ISO 8601 格式字符串:`"2026-05-27T15:30:00+08:00"`,或时间戳(毫秒)。

### 9.5 【强制】金额格式

- 金额传输使用**字符串**或**数字**,统一保留 1 位或 2 位小数。
- 前端展示与计算分离:展示用 `toFixed(1)`,计算用 `Number(x)`。
- **不得**因浮点精度返回 `13.900000001`。

## 10. 注释规范

### 10.1 【强制】文件头注释

每个 JS / Java 文件首部应包含简短的文件说明。

```javascript
/**
 * 购物车页面交互逻辑
 *
 * 职责:
 *   1. 拉取购物车数据 + 用户优惠券
 *   2. 自动选取最优可用券
 *   3. 处理下单
 */
```

### 10.2 【强制】复杂逻辑注释

业务规则、算法、特殊处理必须有注释说明 **为什么**,而非 **是什么**。

```javascript
// 自动选最优券:在满门槛的券中,优先选 discountAmount 最大的
// 不在此处校验 selectedCoupon,recalc() 会再校验一次门槛
var usable = myCoupons.filter(function (c) { return total >= c.conditionAmount; });
```

### 10.3 【推荐】TODO / FIXME

未完成或已知问题应使用统一标记:

```javascript
// TODO(zhangsan): 加购加购车时校验商品已下架
// FIXME: 当 cart.items 为空但 totalAmount > 0 时计算错误
```

## 11. Git 版本管理规范

### 11.1 【强制】分支命名

| 类型     | 命名                  | 示例                      |
| -------- | --------------------- | ------------------------- |
| 主分支   | `main`                | `main`                    |
| 开发分支 | `develop`             | `develop`                 |
| 功能分支 | `feature/<功能名>`    | `feature/coupon-drawer`   |
| 修复分支 | `fix/<问题>`          | `fix/cart-overflow`       |
| 发布分支 | `release/<版本>`      | `release/v1.0.0`          |

### 11.2 【强制】Commit Message

采用 Conventional Commits 规范:

```
<type>(<scope>): <subject>

<body 可选>
```

**type 取值:**

| type     | 含义               |
| -------- | ------------------ |
| feat     | 新功能             |
| fix      | Bug 修复           |
| docs     | 文档变更           |
| style    | 格式调整(不影响逻辑) |
| refactor | 重构(非新功能、非修 bug) |
| perf     | 性能优化           |
| test     | 测试相关           |
| chore    | 构建/工具/依赖     |

**示例:**

```
feat(cart): 不可用优惠券置灰并显示"还差 ¥X"
fix(menu): 修复加号按钮在 iOS 无响应
docs: 补充编码规范文档
```

### 11.3 【强制】.gitignore

项目根目录 `.gitignore` **必须**包含至少以下内容:

```
# 编译产物
backend/target/
*.class

# 日志
*.log

# IDE
.idea/
.vscode/
*.iml

# 本地配置
*.local.*
.env

# 系统
.DS_Store
Thumbs.db
```

## 12. 资源文件规范

### 12.1 【强制】图片命名

格式:`<场景>-<类型>-<描述>.<扩展名>`

| 示例                       | 含义               |
| -------------------------- | ------------------ |
| `home-banner-1.png`        | 首页 第 1 张轮播图 |
| `nav-mine.svg`             | 导航 我的         |
| `menu-product-grape.png`   | 点餐页 商品 葡萄  |
| `mascot-yunbao-144.png`    | 吉祥物 144px      |

### 12.2 【强制】图片格式选择

| 类型               | 格式      | 说明                             |
| ------------------ | --------- | -------------------------------- |
| 图标(单色/双色)  | SVG       | 可缩放,文件小                   |
| 照片、复杂图       | JPG/WebP  | 体积小                           |
| 带透明、需高保真   | PNG       | 仅在必要时使用,注意体积         |
| 动图               | GIF/WebP  | 优先 WebP                        |

### 12.3 【推荐】图片体积控制

- 单张图片 ≤ 200 KB(首屏关键图 ≤ 100 KB)。
- 上线前用 TinyPNG / Squoosh 压缩。
- 移动端 1x 资源 PPI ≤ 144。

### 12.4 【强制】字体引用

H5 项目通过 Google Fonts 引入:

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=..." rel="stylesheet">
```

字体声明集中在 `common.css` 顶部,业务样式中**不得**重复声明 `@font-face`。
